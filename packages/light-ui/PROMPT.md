# 给编码助手的复用提示词

把下面这段和你的项目交给编码助手即可。先运行本仓库示例，再决定接入位置。

> 在我的现有界面接入 Lancer Light UI，保持原布局、字体和内容结构。
>
> 1. 顶部有当前模型入口，中间有对话气泡，右侧有会话工作树。每个会话可有多个子分支，子分支可继续分叉，完成后连回父节点。用稳定的会话 ID、事件 ID、父节点 ID 连接，禁止按最近坐标猜关系。
> 2. 真实的新消息、阶段完成或交付事件触发光线。从对应模型图标和气泡出发，落到该事件的节点。光线与所属工作树颜色一致；每次路径可变化，同一次飞行不抖动；慢起、加速、慢落，默认 1.2 秒。
> 3. 先预留新节点并跟随到可见位置，再发射。不要替用户滚走正在阅读的聊天记录；工作树可单独跟随。历史加载、切换会话不能重播旧光线。节点保存由业务负责，不能只存在于动画中。
> 4. 正在运行的气泡或步骤有细窄的同色流动边框，完成后移除。键盘焦点样式独立保留；不要把鼠标点击当成运行状态。
> 5. 多会话横向排布，分支不挤成细线；超出宽度横向滚动，历史过长纵向滚动。聚焦只展示当前会话并居中，全部会话显示所有根会话。合并保留全部来源连线。
> 6. 交付给一个简短自然语言结论和可打开的文件卡。日志、命令和分支内部提示词默认折叠，不塞进大气泡。
> 7. 使用本库的 createLightLayer / emit，或复用同一套底层 SVG 渲染函数；不要重新写第二套动效。空闲时停帧循环，页面隐藏暂停，卸载时清理，尊重 prefers-reduced-motion。不要每帧触发 React 渲染，也不要用大面积模糊背景模拟光线。
> 8. 接入后实测：单线、分叉、孙分支、多个会话并行、合并、交付、滚动和缩放、切换会话、暂停与销毁。检查光线源 / 目标的语义 ID 和落点；同时验证任务失败、目标暂不可见。演示数据标为演示，不假装真实业务已执行。
>
> 先读项目现有代码和约束，说明接入点与验证方法，然后实现。无关 UI 不要顺手重设计。
