# Lancer 扩展开发指南

Lancer 完整保留了上游 pi-gui 的扩展系统，没有做任何改动。扩展本身就是普通的 **pi 扩展**，所以：

- 同一个扩展在 Lancer、上游 pi-gui 和 pi 命令行里都能加载。
- 扩展配置写在 pi 的配置文件里（`~/.pi/agent/settings.json` 或项目内的 `.pi/settings.json`），Lancer 不另存一份。

本文说明三件事：如何写一个最小扩展，如何给扩展加一个**桌面视图**（显示在侧边面板里的自定义网页界面），以及如何参考上游示例 [`examples/desktop-extensions`](../../examples/desktop-extensions/README.md)。

---

## 1. 扩展能做什么

| 能力                        | 用到的 API                                                      | 在 Lancer 里的表现                      |
| --------------------------- | --------------------------------------------------------------- | --------------------------------------- |
| 斜杠命令                    | `pi.registerCommand(name, { description, handler })`            | 输入框里输入 `/命令名`                  |
| 给智能体添加工具            | `pi.registerTool({...})`                                        | 模型可以调用；时间线里显示工具卡片      |
| 监听会话事件                | `pi.on("session_start" \| "session_shutdown" \| ..., handler)`  | 恢复状态、清理进程等                    |
| 保存会话数据                | `pi.appendEntry(type, data)`                                    | 随会话保存，可在分叉或回溯时恢复        |
| 注册模型提供商              | `pi.registerProvider(id, {...})`                                | 出现在“设置 → 模型与账号”和模型切换器中 |
| **桌面视图**（Lancer 专属） | `registerDesktopView(pi, {...})`（来自 `@lancer/extension-ui`） | 侧边面板 **+（添加标签页）→ 扩展视图**  |

在 pi 命令行里，桌面视图不会显示（`available === false`），但命令和工具照常可用。

## 2. 最小扩展：一个斜杠命令

新建文件 `~/my-pi-extensions/hello/index.ts`：

```ts
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function hello(pi: ExtensionAPI): void {
  pi.registerCommand("hello", {
    description: "打个招呼：/hello 名字",
    async handler(args, ctx) {
      ctx.ui.notify(`你好，${args.trim() || "Lancer"}！`, "info");
    },
  });
}
```

然后在 `~/.pi/agent/settings.json`（对所有项目生效）或某个项目的 `.pi/settings.json`（只对该项目生效）里，把**绝对路径**加入 `extensions` 数组。注意保留文件里原有的其他设置：

```json
{
  "extensions": ["/Users/你的用户名/my-pi-extensions/hello/index.ts"]
}
```

也可以不写配置，直接把扩展放进 pi 会自动发现的目录：

- `~/.pi/agent/extensions/<名字>/index.ts`（全局）
- `<项目>/.pi/extensions/<名字>/index.ts`（仅该项目；需要你信任该项目）

### 在 Lancer 中重新加载

1. 侧边栏点 **扩展**，选择对应工作区，点 **刷新**。这一步会重新发现扩展并显示诊断信息，加载失败时能看到原因。
2. 回到会话后，在输入框输入 `/hello 世界` 试试。
3. 修改扩展代码后：等当前回合结束，在会话里执行 `/reload`；或者在 **扩展** 页面再点一次 **刷新**。

> 小提示：**设置 → 通用 → 技能斜杠命令** 控制技能是否以斜杠命令的形式出现，它和扩展命令互不影响。

## 3. 桌面视图：在侧边面板里放一个自定义界面

桌面视图是一段运行在隔离 iframe 里的浏览器代码，通过 [Chord](https://www.npmjs.com/package/@earendil-works/chord) 与扩展后端通信。添加视图**不需要**修改 Lancer 本身，也不需要新增 IPC。

结构参考上游示例 `examples/desktop-extensions/test-runs/`：

```
test-runs/
├── index.ts      # pi 扩展入口：命令、工具、registerDesktopView（后端）
├── contract.ts   # 前后端共享的服务接口定义（Chord facet）
├── desktop.ts    # 浏览器端：export async function mount(root, host)
├── build.mjs     # 把 desktop.ts 打包成 dist/desktop.js
└── dist/desktop.js
```

后端注册（节选自 `test-runs/index.ts`）：

```ts
import { registerDesktopView } from "@lancer/extension-ui";

registerDesktopView(pi, {
  id: "test-runs",
  title: "Test Runs",
  source: import.meta.url,
  frontend: new URL("./dist/desktop.js", import.meta.url),
  backend: () =>
    defineFacet({
      id: "my.extension.backend",
      setup(env) {
        const state = env.replicatedState(initialState);
        env.provide(MyService, { state /* , 你的方法 */ });
      },
    }),
});
```

前端入口（`desktop.ts`）：

```ts
import type { DesktopViewContext } from "@lancer/extension-ui/browser";

export async function mount(root: HTMLElement, host: DesktopViewContext) {
  host.signal.throwIfAborted();
  // host.theme.background / foreground / accent：跟随 Lancer 的主题配色
  // host 还提供受限的 openFile、prepareTaskDraft 等操作（草稿不会自动发送）
  root.textContent = "Hello from Lancer";
  return () => {
    /* 视图关闭时的清理 */
  };
}
```

要点：

- 先等服务绑定的 `ready()` 完成，再读取状态或订阅。同时监听 `host.signal`：视图关闭后不要继续使用旧的能力对象。
- 后端状态用 `env.replicatedState` 创建，这样它归属于宿主的 Chord 实例，关闭再打开视图时状态还在。
- 关闭视图只会断开连接，不会停用扩展，也不会停止后台任务。
- 不要把 `desktop.ts` 或 `dist/desktop.js` 当作 pi 扩展注册，只注册 `index.ts`。

### 运行上游的两个示例

在本仓库根目录执行（需先完成 `pnpm install`）：

```sh
pnpm --filter @lancer/extension-ui build
node examples/desktop-extensions/pr-review/build.mjs
node examples/desktop-extensions/test-runs/build.mjs
```

把下面两个绝对路径加入目标项目的 `.pi/settings.json`，或全局的 `~/.pi/agent/settings.json`：

```json
{
  "extensions": [
    "/你的路径/lancer/examples/desktop-extensions/pr-review/index.ts",
    "/你的路径/lancer/examples/desktop-extensions/test-runs/index.ts"
  ]
}
```

然后在 Lancer 中：

1. **扩展 → 刷新**，然后返回应用。
2. 打开一个会话，按 ⌥⌘B 打开侧边面板。
3. 点 **+（添加标签页）**，在 **扩展视图** 下选择 **PR Review** 或 **Test Runs**。

`@lancer/extension-ui` 是本仓库内部的工作区包，没有发布到 npm。所以最简单的做法是把你的扩展放在本仓库里（比如 `examples/desktop-extensions/my-ext/`），让它直接通过本仓库的 `node_modules` 解析依赖。若要在仓库外使用，可以按上游 README 的“Install local packages outside this checkout”一节，先用 `pnpm pack` 打包再安装。

### 修改后如何生效

| 改了什么                        | 怎么生效                                                          |
| ------------------------------- | ----------------------------------------------------------------- |
| 前端 `desktop.ts`、CSS          | 重新运行该扩展的 `build.mjs`，然后在视图标签里点 **重新加载视图** |
| 后端 `index.ts`、工具、状态逻辑 | 等当前任务结束或停止，然后在会话中执行 `/reload`                  |
| 前后端共享的 `contract.ts`      | 重新打包前端，执行 `/reload`，再重新打开或重新加载视图            |

### 自检命令（不会启动 Electron）

```sh
pnpm test:extension-examples
pnpm typecheck:extension-examples
node examples/desktop-extensions/test-runs/build.mjs --check
```

## 4. 用扩展接入自己的模型

如果你的模型服务兼容 OpenAI 接口，最简单的方法是使用 **设置 → 模型与账号 → 自定义端点**，不用写代码。

需要更复杂的鉴权或请求改写时，可以写一个扩展，调用 `pi.registerProvider`。参考 `packages/pi-sdk-driver/test/runtime-supervisor-extension-providers.test.mts` 里的 `extensionSource`：

```ts
export default async function myProvider(pi) {
  pi.registerProvider("my-llm", {
    baseUrl: "https://llm.example.com/v1",
    apiKey: "MY_LLM_API_KEY", // 填环境变量名或密钥
    api: "openai-completions",
    models: [
      {
        id: "my-model",
        name: "My Model",
        reasoning: false,
        input: ["text"],
        cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
        contextWindow: 128000,
        maxTokens: 16384,
      },
    ],
  });
}
```

加载后，这些模型会出现在每个会话顶部的模型切换器里。

## 5. 常见问题

- **扩展没有出现**：在 **扩展** 页面点 **刷新** 并查看诊断信息。项目级扩展只有在信任该项目后才会加载。
- **视图列表里没有我的视图**：确认已经运行 `build.mjs` 生成 `dist/desktop.js`，然后在 **添加标签页** 菜单里点 **刷新视图**。
- **Lancer 和 pi-gui 能共用扩展吗？** 可以。两者读取同一个 `~/.pi/agent`，扩展、登录状态、模型和会话都共享。
- 更多细节（失败场景、PR Review 的状态机、打包安装方式）请看上游英文文档：[`examples/desktop-extensions/README.md`](../../examples/desktop-extensions/README.md)、[`pr-review/README.md`](../../examples/desktop-extensions/pr-review/README.md)、[`test-runs/README.md`](../../examples/desktop-extensions/test-runs/README.md)。
